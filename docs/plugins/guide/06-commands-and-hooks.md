# 6. Команды и хуки

Четыре способа вмешаться в работу клиента:

| Что | Метод | Когда срабатывает |
|---|---|---|
| Слеш-команда | `dzg.commands.register('name', fn)` | Пользователь отправил `/name …` |
| Хук перед отправкой | `dzg.messages.onBeforeSend(fn)` | Перед отправкой любого текстового сообщения |
| Фильтр ленты | `dzg.messages.addFilter(fn)` | Клиент решает, показывать ли сообщение |
| Подмена текста | `dzg.messages.addRenderTransform(fn)` | Клиент рисует текст сообщения |

Все четыре возвращают функцию, которая снимает регистрацию.

## Слеш-команды

```js
dzg.commands.register('roll', {
  description: 'Бросить кубик: /roll 20',
  run({ args, chat, replyTo }) {
    const sides = Number(args[0]) || 6;
    dzg.messages.send(chat, `🎲 ${1 + Math.floor(Math.random() * sides)} из ${sides}`, { replyTo });
  },
});

// Короткая форма — сразу функция
dzg.commands.register('now', ({ chat }) => {
  dzg.messages.send(chat, new Date().toISOString());
});
```

Когда пользователь отправляет сообщение, которое начинается с `/roll`,
клиент находит команду, вызывает `run` и **не отправляет** сообщение.

Контекст `run`:

| Поле | Пример для `/roll 20 d` |
|---|---|
| `args` | `['20', 'd']` — слова после команды |
| `rest` | `'20 d'` — всё после команды одной строкой (с переводами строк) |
| `text` | `'/roll 20 d'` — исходный текст |
| `chat` | `Peer` чата, где набрали команду |
| `replyTo` | id сообщения, на которое отвечали, или `0` |

Правила:

- Имя — латиница, цифры и `_`, без учёта регистра: `/Roll` = `/roll`.
  Суффикс `/roll@bot` тоже распознаётся.
- `run` может быть `async`.
- Команды чужих плагинов и свои видны в `dzg.commands.all()`, а выполнить
  любую можно через `dzg.commands.run('/digest 50', chat)` — так делает
  командная палитра `Ctrl+Shift+K`. `description` показывается в палитре, поэтому
  пиши его понятно.
- Сообщения, которые отправляет сам плагин через `dzg.messages.send`,
  команды не запускают (если не передать `runHooks: true`).

## Хук перед отправкой

`onBeforeSend` вызывается перед отправкой каждого текстового сообщения из
поля ввода. Хук может переписать текст или отменить отправку:

```js
dzg.messages.onBeforeSend(({ text, chat }) => {
  // Вернуть строку — заменить текст
  if (chat.type === 'channel') return text + '\n\n— @wetakush';
});

dzg.messages.onBeforeSend(({ text }) => {
  // Вернуть false — не отправлять
  if (/пароль:\s*\S+/i.test(text)) {
    dzg.ui.toast('Похоже на пароль — сообщение не отправлено');
    return false;
  }
});

dzg.messages.onBeforeSend(({ text }) => ({ text: text.replace(/\bкек\b/gi, 'kek') }));
```

| Вернуть | Что будет |
|---|---|
| строку или `{ text }` | Отправится этот текст |
| `false` или `{ cancel: true }` | Сообщение не уйдёт |
| ничего | Как есть |

Контекст: `text` (уже с правками предыдущих хуков), `chat`, `peerId`,
`replyTo`. Хуки всех плагинов выполняются цепочкой: следующий получает
результат предыдущего.

Важно:

- Хук **синхронный**: возвращённый промис не ждут. Ответа сети в хуке не
  дождаться — для этого отмени отправку и отправь сам позже (см. рецепт
  [«Автоперевод исходящих»](../cookbook.md#автоперевод-исходящих)).
- Если хук поменял текст, форматирование исходного сообщения (жирный,
  ссылки под текстом) сбрасывается. Если вернул тот же текст —
  сохраняется.
- Пустой итоговый текст отменяет отправку.
- Хук не вызывается для правок, подписей к файлам и сообщений самих
  плагинов (без `runHooks: true`).
- Если хук сам отправляет сообщение с `runHooks: true`, это сообщение
  пройдёт через хуки других плагинов, но не через его же хук — так хук не
  зациклится на себе.

## Фильтры ленты

Фильтр прячет сообщения из ленты. Вернул `true` — сообщения не видно:

```js
const banned = new Set(dzg.storage.get('banned', []));

dzg.messages.addFilter((m) => banned.has(m.fromId));

dzg.ui.addMessageMenuItem({
  title: 'Скрывать сообщения этого человека',
  when: (m) => !m.out,
  onClick(m) {
    banned.add(m.fromId);
    dzg.storage.set('banned', [...banned]);
    dzg.messages.refilter();
  },
});
```

- Фильтр работает через механизм скрытия сообщений AyuGram и вызывается при
  отрисовке ленты — он должен быть **быстрым, синхронным и без побочных
  эффектов**.
- Результат запоминается для каждого сообщения. Если условие изменилось
  (новые слова, другие настройки), вызови `dzg.messages.refilter()`.
- Сообщение не удаляется — оно просто не показывается. Сними фильтр, и всё
  вернётся.

## Подмена текста при отрисовке

Трансформация меняет только то, **что показано на экране**. Само
сообщение, копирование, пересылка и поиск видят оригинал.

```js
// Цензура
const bad = /\b(блин|капец)\b/gi;
dzg.messages.addRenderTransform((m) => {
  const text = m.text.replace(bad, '***');
  return text === m.text ? null : text;
});

// Подсветить упоминания себя
const me = dzg.users.self();
dzg.messages.addRenderTransform((m) => {
  if (!me || m.out || !me.username) return null;
  return m.text.includes('@' + me.username) ? '🔔 ' + m.text : null;
});
```

- Вернуть строку — показать её. `null`/`undefined` — оставить как есть.
- Заменённый текст показывается без форматирования оригинала.
- Результат кешируется для сообщения; функция вызывается снова, когда
  текст изменился или кто-то добавил/убрал трансформацию. После смены
  своих правил вызови `dzg.messages.refreshRender()`.
- Трансформации всех плагинов применяются по очереди: следующая получает
  результат предыдущей в `message.text`.
- Сервисные сообщения не трогаются. Пока трансформаций нет, клиент вообще
  не вызывает JS при отрисовке.

## Что выбрать

| Задача | Инструмент |
|---|---|
| Действие по запросу пользователя в чате | Команда |
| Исправить, дополнить или запретить исходящее | `onBeforeSend` |
| Спрятать сообщения целиком | `addFilter` |
| Изменить вид текста, не трогая сообщение | `addRenderTransform` |
| Отреагировать на входящее | Событие `message.new` |
| Кнопка рядом с полем ввода | `dzg.ui.compose.addButton` |
