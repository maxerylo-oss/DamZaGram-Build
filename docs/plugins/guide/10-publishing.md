# 10. Публикация

Плагин готов — пора поделиться. В DamZaGram плагин ставится в два клика:
из файла, по ссылке или прямо из чата. Подробности установщика — в
[manager.md](../manager.md).

## Форматы

### Папка и `.dzg.zip`

Обычный плагин — папка с `manifest.json`. Для распространения заархивируй
её в `.zip`, лучше с расширением **`.dzg.zip`**:

```sh
cd tdata/plugins
zip -r word-counter.dzg.zip word-counter -x '*/node_modules/*' '*/.git/*'
```

Установщик найдёт самый верхний `manifest.json` в архиве и возьмёт всё, что
лежит рядом, поэтому подходят и архивы GitHub (`repo-main/manifest.json`).
Папки `.git`, `node_modules`, `.vscode`, `.idea`, `__MACOSX` пропускаются.
Лимит — 32 МБ.

### Плагин из одного файла

Маленький плагин удобнее раздавать одним `.js`. Манифест собирается из шапки
комментариев:

```js
// ==DamZaGram Plugin==
// @id          shout
// @name        Shout
// @version     1.2.0
// @author      @wetakush
// @description Команда /shout: отправляет текст капсом.
// @setting     {"key":"suffix","type":"string","title":"Хвост","default":"!!!"}
// ==/DamZaGram Plugin==

dzg.commands.register('shout', ({ chat, rest }) => {
  dzg.messages.send(chat, rest.toUpperCase() + dzg.settings.get('suffix'));
});
```

| Ключ | Значение |
|---|---|
| `@id` | id; если нет — из `@name`, иначе из имени файла |
| `@name`, `@version`, `@author` | Как в манифесте (`@version` по умолчанию `1.0.0`) |
| `@description` | Описание; несколько строк склеиваются |
| `@type` | `module` (по умолчанию) или `script` |
| `@setting` | Одна запись схемы настроек — JSON в одну строку |
| `@settings` | Вся схема — JSON-массив в одну строку |
| любой другой `@ключ` | Попадёт в манифест строкой (`@homepage`, `@license`) |

Подойдёт и блок `/** … */`. Рамка `==DamZaGram Plugin==` необязательна.
При установке файл станет `tdata/plugins/<id>/main.js`, рядом появится
`manifest.json`.

## Как распространять

| Способ | Как ставит пользователь |
|---|---|
| Файл в чате | Отправь `my-plugin.dzg.zip`, `my-plugin.dzg.js` или `my-plugin.plugin.js` в любой чат или канал. Клик по файлу открывает окно установки |
| GitHub | **Плагины → Установить… → По ссылке**: `https://github.com/user/repo`, `…/tree/dev`, `…/blob/main/x.plugin.js` |
| Прямая ссылка | Ссылка на `.zip` или `.js` |
| Файл или папка | Перетащить на раздел «Плагины» или **Установить… → Из файла** |
| Из другого плагина | `dzg.plugins.promptInstall(url)` — «магазин плагинов» |

Перед установкой пользователь всегда видит окно: название, версия, автор,
id, описание, размер, источник и предупреждение о полном доступе. Если
плагин с таким id уже стоит, окно предложит **Обновить**: файлы заменятся,
а хранилище и настройки останутся.

Канал с плагинами — отличный формат: каждый пост — файл `.dzg.zip` с
описанием, подписчики ставят по клику.

## Версии и обновления

- Пиши версию в формате semver: `1.4.2`. Увеличивай её при каждом
  выпуске — по ней окно установки показывает, что это обновление.
- Не меняй `id` между версиями: по нему клиент понимает, что это тот же
  плагин, и сохраняет данные.
- Меняешь формат данных в `storage` — храни номер схемы и мигрируй при
  старте:

```js
const SCHEMA = 2;
if (dzg.storage.get('schema', 1) < 2) {
  const old = dzg.storage.get('words', '');
  dzg.storage.set('words', old.split(',').map((w) => w.trim()).filter(Boolean));
  dzg.storage.set('schema', SCHEMA);
}
```

Автообновление из GitHub-релизов можно сделать прямо в плагине через
`dzg.plugins.inspect` и `dzg.plugins.promptInstall` — пример в
[api/plugins.md](../api/plugins.md#автообновление-с-github).

## Безопасность

Плагин работает с правами пользователя: читает переписку, отправляет
сообщения, ходит в сеть, пишет файлы. Песочницы, которая бы это
ограничивала, нет. Поэтому:

**Автору плагина:**

- Не отправляй данные пользователя на свои серверы без явного согласия и
  описания в `description`. Если плагин ходит в сеть, напиши, куда и зачем.
- Ключи API и токены — в настройках (`type: "string"`), не в коде и не в
  логе.
- Перед разрушительными действиями (удаление, выход из чатов, массовая
  отправка) спрашивай `dzg.ui.confirm`.
- Соблюдай лимиты Telegram: не рассылай сообщения пачками, обрабатывай
  `FLOOD_WAIT`. Аккаунт за спам блокируют — и это будет аккаунт
  пользователя.
- Убирай за собой в `unload`: цвета, спрятанные виджеты.
- Не выполняй код, пришедший из сети или из сообщений (`eval`,
  `new Function` на чужих данных).

**Пользователю:**

- Ставь плагины из источников, которым доверяешь. Плагин из одного файла
  проще всего прочитать перед установкой.
- Обрати внимание на `dzg.http`, `dzg.api.call`, `dzg.messages.send` и
  `dzg.fs.write` в коде — это места, где плагин что-то отправляет или
  меняет.
- Ненужный плагин выключи или удали — выключенный плагин не выполняется
  вообще.

## Чек-лист перед выпуском

- [ ] В манифесте заполнены `id`, `name`, `version`, `author`, `description`.
- [ ] Версия увеличена.
- [ ] У каждой настройки есть `default`, у неочевидных — `description`.
- [ ] Плагин не реагирует на свои сообщения (`m.out`) и не зацикливается.
- [ ] Всё, что меняется напрямую (тема, чужие виджеты), возвращается в
      `unload`.
- [ ] Данные пишутся в `dzg.storage` или `dzg.plugin.dataDir`, а не в папку
      плагина.
- [ ] Ошибки сети и `FLOOD_WAIT` обработаны.
- [ ] Тесты в песочнице проходят:
      `tools/damza/sandbox.py main.js my.test.js`.
- [ ] Плагин проверен в клиенте: включение, выключение, перезагрузка,
      смена настроек.

## Встроенные плагины

Десять плагинов идут вместе с клиентом (`"builtin": true` в манифесте) и
обновляются вместе с ним. Если хочешь заменить встроенный плагин своей
версией, убери из её манифеста `"builtin": true` — клиент перестанет его
трогать. Подробнее — в [builtins.md](../builtins.md#свой-плагин-вместо-встроенного).
