# Менеджер плагинов DamZaGram

Всё про то, как ставить, создавать, настраивать и отлаживать плагины
DamZaGram без единой строчки C++. Автор DamZaGram и менеджера плагинов —
[@wetakush](https://t.me/wetakush).

Где открыть менеджер:

- главное меню (три полоски слева) → **Плагины**;
- **Настройки → Плагины**;
- `Ctrl+Shift+P` из любого места клиента;
- из кода плагина: `dzg.plugins.openManager()`.

> Плагины получают **полный доступ** к клиенту, аккаунту, перепискам,
> файлам и сети. Ставь только тот код, которому доверяешь. Окно установки
> всегда напоминает об этом.

## Раздел «Плагины»

Сверху — сводка (сколько установлено, сколько работает, сколько с
ошибками) и кнопки:

| Кнопка | Что делает |
|---|---|
| **Установить…** | Меню: из файла (`.zip`, `.js`), из папки, по ссылке |
| **Создать плагин** | Мастер нового плагина, см. [ниже](#создать-плагин) |
| **DevTools** | Окно консоли и живого лога, см. [ниже](#devtools) |
| **Открыть папку** | `<папка данных>/tdata/plugins/` |
| **Перезагрузить все** | Перечитать папку и перезапустить все плагины |

Переключатель **«Горячая перезагрузка при изменении файлов»** следит за
файлами плагинов: сохранил `main.js` — плагин перезапустился сам. Поле
**«Поиск плагинов»** фильтрует список по названию, id, автору и описанию.

Каждый плагин — карточка:

- аватар-буква с точкой статуса: зелёная — работает, красная — ошибка,
  без точки — выключен;
- название, версия, автор, пометки `встроенный` и `script`;
- описание и последняя ошибка (красным, текст можно выделить и скопировать);
- переключатель включения справа (клик по шапке карточки тоже переключает);
- кнопки **Настройки** (если у плагина есть схема настроек), **Лог**,
  **Консоль** (DevTools для этого плагина), **Перезагрузить**, **Папка**,
  **Удалить**.

**Удалить** спрашивает подтверждение и может заодно стереть сохранённые
данные плагина (`tdata/plugins_data/<id>.json`). Встроенные плагины
удалить нельзя — клиент возвращает их при каждом запуске, — поэтому для них
кнопка называется «Удалить (выключит)» и просто выключает плагин.

## Установка

### Из файла или папки

**Установить… → Из файла** принимает `.zip` и `.js`, **Из папки** — папку с
`manifest.json`. Ещё проще — **перетащить** файл или папку прямо на
раздел «Плагины».

Перед установкой всегда открывается окно с манифестом: название, версия,
автор, id, описание, число файлов и размер, источник, предупреждение о
полном доступе и галочка «Сразу включить». Если плагин с таким id уже
есть, окно покажет установленную версию и предложит **Обновить** — папка
плагина будет заменена, данные (`storage`, настройки) останутся.

### По ссылке

**Установить… → По ссылке** (если в буфере обмена ссылка — она подставится
сама). Понимает:

| Ссылка | Что скачается |
|---|---|
| `https://…/plugin.dzg.zip`, `https://…/x.zip` | архив как есть |
| `https://…/plugin.js` | плагин из одного файла |
| `https://github.com/user/repo/blob/main/x.plugin.js` | raw-версия файла |
| `https://github.com/user/repo` | архив ветки по умолчанию |
| `https://github.com/user/repo/tree/dev` | архив ветки `dev` |

Лимит — 32 МБ на пакет. Если по ссылке пришла HTML-страница, установщик
так и скажет.

### Из чата

Файлы с именами `*.dzg.zip`, `*.dzg.js` и `*.plugin.js`, присланные в
любой чат, открывают окно установки прямо по клику (после загрузки).
Файлы AyuGram/exteraGram `*.plugin` (Python) по-прежнему открывают своё
окно с информацией — это другой формат, DamZaGram их не запускает.

Хочешь поделиться плагином — заархивируй папку в `my-plugin.dzg.zip` или
сохрани однофайловый плагин как `my-plugin.plugin.js` и отправь в чат.

## Форматы

### Папка и `.dzg.zip`

Плагин — это папка в `tdata/plugins/`:

```
my-plugin/
  manifest.json
  main.js
  lib/…            любые дополнительные файлы (import './lib/x.js')
```

Архив `.zip` / `.dzg.zip` — та же папка. `manifest.json` может лежать в
корне архива или внутри одной папки верхнего уровня (так выглядят архивы
GitHub) — установщик найдёт самый верхний `manifest.json` и возьмёт всё,
что лежит рядом с ним. Папки `.git`, `node_modules`, `.vscode`, `.idea`,
`__MACOSX` пропускаются. Если в архиве нет манифеста, но есть ровно один
`.js`, он ставится как однофайловый плагин.

Поля `manifest.json` описаны в [README](README.md#манифест). Обязательно
только одно: файл `main` (по умолчанию `main.js`) должен существовать.
`id` — латиница, цифры, `-`, `_`, `.`, до 64 символов, начинается с буквы
или цифры; если его нет, берётся имя папки.

### Плагин из одного `.js`

Один файл с шапкой из комментариев — манифест соберётся из неё. Поддерживаются
и `//`-строки, и блок `/** … */`, шапка читается до первой строки кода.

```js
// ==DamZaGram Plugin==
// @id          shout
// @name        Shout
// @version     1.2.0
// @author      @wetakush
// @description Команда /shout: отправляет текст капсом.
// @description Вторая строка описания допишется к первой.
// @type        module
// @setting     {"key":"suffix","type":"string","title":"Хвост","default":"!!!"}
// @setting     {"key":"emoji","type":"bool","title":"Добавлять 📢","default":true}
// ==/DamZaGram Plugin==

dzg.commands.register('shout', ({ chat, rest }) => {
  const prefix = dzg.settings.get('emoji') ? '📢 ' : '';
  dzg.messages.send(chat.id, prefix + rest.toUpperCase() + dzg.settings.get('suffix'));
});
```

| Ключ | Значение |
|---|---|
| `@id` | id плагина; если нет — из `@name`, а если нет и его — из имени файла (`shout.plugin.js` → `shout`) |
| `@name` | название (по умолчанию id) |
| `@version` | версия (по умолчанию `1.0.0`) |
| `@author`, `@description` | автор и описание; несколько `@description` склеиваются |
| `@type` | `module` (по умолчанию) или `script` |
| `@setting` | одна запись схемы настроек, JSON-объект в одну строку |
| `@settings` | вся схема сразу, JSON-массив в одну строку |
| любые другие `@ключ` | попадут в манифест как строки (`@homepage`, `@license`…) |

Строки `==DamZaGram Plugin==` необязательны, это просто красивая рамка.
При установке файл кладётся в `tdata/plugins/<id>/main.js`, рядом
генерируется `manifest.json`.

## Настройки плагина

Окно **Настройки** строится из `settings` в манифесте. Типы:

| `type` | Контрол | Дополнительные поля |
|---|---|---|
| `bool` | чекбокс | — |
| `string` | однострочное поле | — |
| `text` | многострочное поле | — |
| `number` | поле с проверкой | `min`, `max`, `integer: true` (или `step: 1`) |
| `select` | радиокнопки (до 4 вариантов) или выпадающий список | `options`, `style: "dropdown"` |
| `color` | поле `#RRGGBB` / `#RRGGBBAA` + образец цвета; клик по образцу — палитра | — |

У любой записи есть `key`, `title`, `default` и необязательное
`description` — серая подсказка под контролом. Варианты `select` —
массив объектов `{ "value": …, "title": "…" }` или просто значений.

```json
"settings": [
  { "key": "enabled", "type": "bool", "title": "Работать", "default": true },
  { "key": "limit", "type": "number", "title": "Лимит", "default": 10, "min": 1, "max": 100, "integer": true },
  { "key": "mode", "type": "select", "title": "Режим", "default": "fast",
    "options": [ { "value": "fast", "title": "Быстро" }, { "value": "safe", "title": "Аккуратно" } ] },
  { "key": "accent", "type": "color", "title": "Цвет", "default": "#8774e1",
    "description": "Им будут подсвечиваться найденные сообщения" }
]
```

Кнопка **Сбросить** возвращает значения по умолчанию (применяются по
**Сохранить**). Плагин получает `settings.changed` только для реально
изменившихся ключей. Неверное число или цвет подсвечивается красным, и
окно не закрывается.

## Создать плагин

**Создать плагин** спрашивает название, id (подставляется из названия, пока
ты его не поменяешь), описание и автора (по умолчанию — твой @username).
Затем:

1. создаёт `tdata/plugins/<id>/`:
   - `manifest.json` — с примером настроек (`string`, `select`, `bool`);
   - `main.js` — ES-модуль с примерами: тост на `ready`, команда
     `/<id>`, пункт меню сообщения, реакция на `message.new` и
     `settings.changed`;
   - `jsconfig.json` и `types/*.d.ts` — типы всего API, чтобы VS Code
     подсказывал `dzg.` и проверял код;
2. включает плагин;
3. открывает его папку.

Дальше просто редактируй `main.js` — при включённой горячей перезагрузке
плагин перезапускается на каждое сохранение, ошибки приходят тостом и
видны в карточке.

Типы вшиты в клиент при сборке. После изменения файлов в
`docs/plugins/types/` разработчику клиента нужно запустить
`tools/damza/embed_types.py` — он перегенерирует
`damza/plugins/plugin_types_embedded.cpp`.

## DevTools

**DevTools** — отдельное окно (его можно двигать и растягивать, клиент
при этом остаётся доступен):

- сверху выбор плагина — любой загруженный плагин или **песочница**;
- слева — история: введённый код и результат (`←`) или ошибка (`✕`);
- справа — живой хвост лога выбранного плагина (обновляется сам,
  `console.log` из консоли тоже попадает сюда);
- снизу — многострочное поле, **Ctrl+Enter** выполняет код;
- кнопки **Выполнить**, **Очистить**, **Перезагрузить** (плагин),
  **Скопировать лог**, **Папка**.

Открыть DevTools сразу для нужного плагина — кнопка **Консоль** в его
карточке, кнопка **DevTools** в окне лога или `dzg.plugins.openDevTools(id)`.

Как выполняется код:

- в **глобальной** области плагина: доступен весь `dzg`, глобальные
  переменные и функции плагина. Переменные ES-модуля (`const` в
  `main.js`) снаружи не видны — что нужно для отладки, клади в
  `globalThis`;
- результат показывается как JSON (функции и ошибки — текстом);
- `const`/`let` в консоли живут до перезагрузки плагина;
- **top-level `await` работает**: такой код оборачивается в async-функцию,
  а результат приходит в лог строкой `[devtools] => …` (ошибка —
  `[devtools] x …`).

```js
dzg.chats.current()
await dzg.chats.info(dzg.chats.current())
dzg.plugins.list().filter((p) => p.error)
```

**Песочница** — служебный плагин `devtools` (тип `script`), который
создаётся при первом обращении: там удобно пробовать API, ничего не
ломая. Это обычный плагин — его можно выключить или удалить.

## Плагины, которые управляют плагинами

Всё, что умеет менеджер, доступно и из JS через `dzg.plugins`: список,
включение, установка по ссылке, удаление, лог, настройки и код в другом
плагине. Подробности и примеры (магазин, профили, автообновление) — в
[api/plugins.md](api/plugins.md).

## Где что лежит

| Путь | Что там |
|---|---|
| `tdata/plugins/<id>/` | плагины |
| `tdata/plugins_data/<id>.json` | `dzg.storage` плагина |
| `tdata/plugins_data/_state.json` | какие плагины включены, их настройки, горячая перезагрузка |
| `tdata/plugins_data/_staging/` | временная папка установщика |
