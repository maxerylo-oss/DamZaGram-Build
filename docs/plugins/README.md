# Плагины DamZaGram

DamZaGram — десктопный клиент Telegram на базе AyuGram с полноценной системой
плагинов на JavaScript. Автор — [@wetakush](https://t.me/wetakush).

Плагин — это папка с `manifest.json` и `main.js`. Он запускается внутри клиента,
видит те же чаты и сообщения, что и ты, и может менять поведение и интерфейс
клиента прямо на ходу — без пересборки и без перезапуска.

> Плагины получают **полный доступ** к клиенту, аккаунту, перепискам, файлам и
> сети. Ставь только тот код, которому доверяешь.

## Что умеют плагины

- **Слушать всё, что происходит:** новые, изменённые и удалённые сообщения,
  реакции, «печатает…», кто появился в сети, непрочитанные, открытие чата,
  фокус окна, ввод текста, смена темы — [16 событий](guide/02-events.md).
- **Писать и управлять сообщениями:** отправка с Markdown и HTML, ответы,
  отложенная отправка, правка, удаление, пересылка, реакции, закрепление,
  файлы и альбомы, скачивание медиа, нажатие кнопок ботов.
- **Читать историю и искать** на сервере: постранично, по всем чатам, по
  типу вложений, асинхронным итератором по всей истории.
- **Управлять чатами:** список и папки, вступить по ссылке, выйти, mute,
  архив, закрепить, прочитать, участники, создание групп и каналов,
  приглашения, кик и бан.
- **Встраиваться в интерфейс:** пункты контекстных меню и главного меню,
  кнопки в шапке чата и у поля ввода, горячие клавиши, уведомления,
  диалоги, боковые панели, свои виджеты и доступ к **любому** виджету
  клиента.
- **Перехватывать и переписывать:** слеш-команды, хук перед отправкой,
  фильтры ленты (скрыть сообщения), подмена текста при отрисовке.
- **Ходить в сеть и хранить данные:** HTTP с промисами, постоянное
  хранилище, настройки с готовым окном, файлы, буфер обмена.
- **Вызывать любой метод Telegram API** (сырой MTProto, слой 229) и
  слушать сырые обновления сервера — если в обёртках чего-то нет.
- **Управлять другими плагинами:** включать, перезагружать, ставить по
  ссылке, выполнять код в другом плагине.
- **Перекрашивать клиент:** любые цвета палитры на лету, ночной режим.

Всё это — современный JavaScript (ES2023, `async`/`await`, ES-модули) с
подсказками VS Code для каждого метода.

## Быстрый старт за 5 минут

1. Открой **Настройки → Плагины** (или `Ctrl+Shift+P`, когда фокус не в
   поле ввода, или главное меню → **Плагины**).
2. Нажми **Создать плагин**, введи название, например «Мой первый». Клиент
   создаст папку плагина с `manifest.json`, `main.js`, типами для VS Code,
   включит плагин и откроет папку. Появится тост с приветствием — плагин уже
   работает.
3. Открой `main.js` в редакторе и замени всё на:

   ```js
   dzg.on('message.new', (message) => {
     if (!message.out && /привет/i.test(message.text)) {
       dzg.ui.toast(`${message.fromName} поздоровался в «${message.chat.name}»`);
     }
   });

   dzg.commands.register('dice', async ({ chat }) => {
     dzg.messages.send(chat, `🎲 ${1 + Math.floor(Math.random() * 6)}`);
   });
   ```

4. Сохрани файл. Пока включена **горячая перезагрузка**, плагин
   перезапускается сам на каждое сохранение. Напиши в любом чате `/dice` —
   команда не уйдёт в чат, вместо неё плагин отправит кубик.

Подробный разбор — в гайде [«Первый плагин»](guide/01-first-plugin.md).

## Анатомия плагина

```
tdata/plugins/my-plugin/
  manifest.json      описание плагина и схема настроек
  main.js            точка входа (ES-модуль)
  lib/util.js        любые свои файлы: import { x } from './lib/util.js'
  jsconfig.json      подсказки VS Code (создаёт мастер)
  types/*.d.ts       типы API (создаёт мастер)
```

Папка плагинов — `<папка данных>/tdata/plugins/`: в Linux это
`~/.local/share/DamZaGramDesktop/tdata/plugins/`, в Windows —
`%APPDATA%\DamZaGram Desktop\tdata\plugins\`. Быстрее всего открыть её
кнопкой **Открыть папку** в разделе «Плагины». Из кода — `dzg.app.pluginsPath`.

### Манифест

```json
{
  "id": "my-plugin",
  "name": "Мой плагин",
  "version": "1.0.0",
  "author": "@wetakush",
  "description": "Что делает плагин — одной строкой",
  "main": "main.js",
  "type": "module",
  "settings": [
    { "key": "word", "type": "string", "title": "Слово", "default": "привет" }
  ]
}
```

| Поле | По умолчанию | Описание |
|---|---|---|
| `id` | имя папки | Уникальный id: латиница, цифры, `-`, `_`, `.`, до 64 символов, первый символ — буква или цифра. Плагин с другим id клиент не загрузит |
| `name` | `id` | Название в менеджере плагинов |
| `version` | `0.0.0` | Версия, лучше в формате semver (`1.2.3`) — по ней установщик понимает, что это обновление |
| `author` | — | Автор, например `@username` |
| `description` | — | Описание в карточке плагина |
| `main` | `main.js` | Входной файл |
| `type` | `module` | `module` — ES-модуль (`import`, top-level `await`); `script` — классический скрипт с глобальной областью |
| `settings` | `[]` | Схема настроек — клиент сам построит окно, см. ниже |
| `builtin` | `false` | Ставится только во встроенные плагины: клиент обновляет такой плагин сам |
| `enabledByDefault` | `true` | Только для встроенных: `false` — не включать при первом запуске |

Любые другие поля (`homepage`, `license`…) просто хранятся в манифесте.

### Схема настроек

Из `settings` клиент сам строит окно **Настройки** плагина. Значения читает
`dzg.settings.get(key)`, а при изменении приходит событие
`settings.changed`.

| `type` | Контрол | Дополнительные поля |
|---|---|---|
| `bool` | чекбокс | — |
| `string` | однострочное поле | — |
| `text` | многострочное поле | — |
| `number` | поле с проверкой | `min`, `max`, `integer: true` (или `step: 1`) |
| `select` | радиокнопки (до 4 вариантов) или выпадающий список | `options`, `style: "dropdown"` |
| `color` | поле `#RRGGBB` / `#RRGGBBAA`, образец и палитра по клику | — |

У каждой записи есть `key`, `title`, `default` и необязательное
`description` — серая подсказка под контролом. Варианты `select` — массив
`{ "value": …, "title": "…" }` или просто значений.

```json
"settings": [
  { "key": "enabled", "type": "bool", "title": "Работать", "default": true },
  { "key": "limit", "type": "number", "title": "Сколько сообщений", "default": 50, "min": 1, "max": 500, "integer": true },
  { "key": "mode", "type": "select", "title": "Режим", "default": "short",
    "options": [ { "value": "short", "title": "Коротко" }, { "value": "full", "title": "Подробно" } ] },
  { "key": "accent", "type": "color", "title": "Цвет подсветки", "default": "#C8F135",
    "description": "Им подсвечиваются найденные сообщения" }
]
```

Плагин можно написать и **одним файлом** `.js` с шапкой `// @name …` —
манифест соберётся из неё, см. [«Публикация»](guide/10-publishing.md).

## Жизненный цикл

1. **Загрузка.** Клиент создаёт для плагина отдельный движок JavaScript,
   строит объект `dzg` и выполняет `main.js` сверху вниз. Здесь
   регистрируй обработчики, команды, кнопки и меню. На загрузку есть
   10 секунд.
2. **`ready`.** Сразу после загрузки приходит событие `ready` — удобное
   место для первого тоста или запуска таймеров.
3. **Работа.** Клиент вызывает обработчики событий, команды, хуки и клики.
   Каждый вызов должен уложиться в 3 секунды — долгую работу делай через
   `await` (сеть, история сервера), а не циклами. События получают только
   плагины, которые на них подписаны, а события сообщений и большинство
   других приходят на следующей итерации цикла событий клиента, не внутри
   его уведомлений (подробно — в [гайде по событиям](guide/02-events.md#когда-приходят-события)).
4. **`unload`.** При выключении, перезагрузке, обновлении плагина или выходе
   из клиента приходит `unload` (при выходе — пока окна и аккаунты ещё
   доступны). После него клиент **сам** убирает всё, что
   зарегистрировал плагин: таймеры, команды, хуки, фильтры, пункты меню,
   кнопки, горячие клавиши, панели, подписки `dzg.api.onUpdate`,
   трансформации текста и цвета, заданные через `dzg.theme`. Сам убирай
   только то, что менял напрямую: свои виджеты в чужих окнах, спрятанные
   виджеты клиента.

Переменные между перезапусками не живут — каждый запуск начинается с нуля.
Для долговременных данных есть `dzg.storage` (файл
`tdata/plugins_data/<id>.json`) и `dzg.settings`.

Пока в разделе «Плагины» включена **горячая перезагрузка**, клиент следит
за файлами плагинов (и в подпапках) и перезапускает плагин при каждом
сохранении, а ошибки показывает тостом. Файлы, которые плагин сам записал
через `dzg.fs.write`, перезапуска не вызывают. Без горячей перезагрузки
ошибки видны только в карточке плагина и в логе.

Включение, выключение и перезагрузка плагинов никогда не происходят
посреди работы JS: если в этот момент выполняется код какого-то плагина,
менеджер применит изменение сразу после него. Установка нового плагина не
перезапускает остальные.

## Окружение JavaScript

Плагины выполняет **QuickJS-ng** — компактный движок с полной поддержкой
современного стандарта. Каждый плагин живёт в своём движке: свои
глобальные переменные, свой `dzg`, своё хранилище. Весь код выполняется в
главном потоке клиента.

**Есть всё из ES2023 и новее:** `async`/`await` и top-level `await`,
классы с приватными полями `#x`, `?.`, `??`, `??=`, spread объектов,
деструктуризация, генераторы и асинхронные генераторы (`for await`),
`BigInt`, `Map`/`Set` (и методы `union`/`intersection`), `WeakRef`,
`Array.prototype.findLast`/`toSorted`/`at`, `Object.groupBy`,
`Promise.withResolvers`, итераторные хелперы, регулярные выражения с
`\p{L}`, lookbehind и флагом `v`, `atob`/`btoa`, `performance.now()`.

**ES-модули.** `main.js` по умолчанию — ES-модуль, поэтому работают
`import` и `export`:

```js
// main.js
import { formatDuration } from './lib/time.js';
import * as store from './lib/store.js';
```

Пути относительные — от файла, который импортирует (расширение `.js` можно
не писать). Пакетов `node_modules` нет: нужную библиотеку положи файлом в
папку плагина. JSON импортировать нельзя — читай его через
`JSON.parse(dzg.fs.read('data.json'))` или оформи как `export default {...}`.

**CommonJS.** Для старого кода и для `type: "script"` есть `dzg.require`:

```js
// lib/math.js
module.exports = { clamp: (x, a, b) => Math.min(b, Math.max(a, x)) };

// main.js
const { clamp } = dzg.require('./lib/math.js');
```

Путь в `dzg.require` всегда считается от папки плагина, модуль выполняется
один раз и кешируется.

**Чего нет**, потому что это не браузер и не Node.js:

| Нет | Чем заменить |
|---|---|
| `fetch`, `XMLHttpRequest` | `dzg.http.fetch(url, options)` |
| `localStorage` | `dzg.storage` |
| `fs`, `path`, `process` | `dzg.fs`, `dzg.plugin.dir`, `dzg.app` |
| `Intl`, `toLocaleString('ru-RU')` | Форматируй даты и числа сам (`padStart`, `toFixed`) |
| `TextEncoder` / `TextDecoder` | `dzg.api.toBase64(text)` / `dzg.api.fromBase64(b64, 'text')` |
| `structuredClone` | `JSON.parse(JSON.stringify(x))` |
| DOM, `document`, `window` | `dzg.ui` и виджеты клиента |

**Ограничения.** Один вызов из клиента в плагин (обработчик события,
команда, клик, таймер) может работать не дольше **3 секунд**, загрузка
`main.js` — не дольше **10 секунд**. Если время вышло, скрипт
останавливается с ошибкой `Script took longer than 3000 ms and was stopped`,
а клиент продолжает работать. Память — до 256 МБ на плагин, стек — 1 МБ
(в Windows 512 КБ).

**Значения, которые уходят в клиент** (аргументы `dzg.*`, `storage.set`,
результаты хуков), — это JSON-подобные данные: свойства-функции и
`undefined` пропускаются, циклическая ссылка становится `null`. У одного значения есть
предел размера (около 4 млн элементов): больше — и вызов бросит
`RangeError: value is too large for native code`.

## Идентификаторы

- Чаты и пользователи — объекты `Peer`. Их `id` — **строка** (64-битные id
  не помещаются в `number`). Везде, где нужен чат, можно передать строку
  `id` или сам `Peer`.
- `Peer.tgId` — «голый» Telegram id, как в Bot API и ссылках `t.me/c/…`.
- Сообщение адресуется парой `(чат, id)`, `id` — число. Вместо id почти
  везде можно передать сам объект `Message`.
- Асинхронные методы возвращают `Promise` и при ошибке отклоняются с
  `Error` (код Telegram вроде `FLOOD_WAIT_10` в `message`). Синхронные не
  бросают исключений, если что-то не найдено: возвращают `null`, `false`
  или `[]`.

## Подсказки в редакторе

Мастер **Создать плагин** кладёт рядом с плагином `jsconfig.json` и папку
`types/` — VS Code сразу начинает подсказывать `dzg.` с описанием каждого
метода и проверять типы. Для плагина, созданного вручную, скопируй папку
[`docs/plugins/types`](types) в плагин и добавь `jsconfig.json`:

```json
{
  "compilerOptions": { "checkJs": true, "target": "ES2023", "module": "ES2022" },
  "include": ["**/*.js", "types/*.d.ts"]
}
```

## FAQ

**Плагин не появился в списке.** В папке плагина должен лежать
`manifest.json` с корректным JSON (ошибка разбора видна в карточке). Если
папку создали вручную, нажми **Перезагрузить все**.

**Плагин включён, но ничего не делает.** Посмотри карточку: красный текст —
ошибка загрузки. Кнопка **Лог** покажет полный стек. Частая причина — опечатка
в имени события: `dzg.on('message.New')` не сработает никогда.

**Можно ли `async`/`await`?** Да, везде: в обработчиках событий, командах,
кликах, на верхнем уровне модуля.

**Почему переменные сбрасываются?** Каждый запуск плагина начинается с чистого
движка. Храни данные в `dzg.storage` — он переживает перезапуск плагина и
клиента.

**Можно ли подключить npm-пакет?** Пакеты не ставятся, но почти любую
библиотеку без зависимостей от Node.js можно положить файлом (ESM-сборку)
в папку плагина и импортировать относительным путём.

**Как отправить сообщение от имени плагина так, чтобы его не перехватил мой
же `onBeforeSend`?** `dzg.messages.send` по умолчанию не запускает хуки и
команды. Нужна обработка — передай `{ runHooks: true }`.

**Как сделать то, чего нет в API?** Почти всё в Telegram доступно через
[`dzg.api.call`](guide/08-raw-mtproto.md), а любой виджет клиента — через
`dzg.ui.find`.

**Плагин подвесит клиент?** Бесконечный цикл остановит сторожевой таймер
через 3 секунды, исключения ловятся и пишутся в лог. Но плагин всё равно
может, например, отправить сообщения или удалить чат — поэтому ставь только
проверенный код.

**Работают ли плагины exteraGram / AyuGram (`.plugin`, Python)?** Нет, это
другой формат. DamZaGram запускает только JavaScript-плагины.

**Где данные плагина?** `tdata/plugins_data/<id>.json` — `dzg.storage`;
`tdata/plugins_data/_state.json` — какие плагины включены и их настройки.
`dzg.plugin.dataDir` — папка для своих файлов.

**С каким аккаунтом работает API?** С активным. Переключить —
`dzg.accounts.switchTo(index)`. А вот `message.new`, `message.edited` и
`message.deleted` приходят от **всех** аккаунтов, в которые выполнен вход.
Аккаунт-получатель — в `message.selfId`: если плагин отвечает или
что-то делает с сообщением, сравни его с `dzg.users.self().id`.
